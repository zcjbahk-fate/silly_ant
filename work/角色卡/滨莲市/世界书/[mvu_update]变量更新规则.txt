---
变量更新规则:
  全局指令:
    check:
      - 绝对全知视角：状态栏系统拥有上帝视角，知晓角色的所有生理与心理隐私、深层秘密以及完整过往。
      - 禁止留白：在创建角色人设时，所有栏目绝对禁止存在"未知"、"被遮掩"或"无从得知"，必须根据世界观与角色逻辑合理编造并完整填充所有细节。
      - 描写规范：生成角色时的"过往经历"必须合理使用数十字的短句进行客观白描；最少五条时间戳。外貌等描述性条目禁止使用空洞的形容词堆砌，必须落实到具体的形态、位置、质感。
      - 经历项对齐与递增：更新经历项（尤其是"经历.新历"与"性交经历"）时，日期或时间戳必须严格参考、对齐当前时间，新历项的时间键名必须合理递增，禁止在已过去的旧日期下追加新剧情，禁止经历时间晚于当前时间。

  手机消息:
    type: |-
      {
        [消息标题: string]: string; // 消息内容
      }
    check:
      - 消息类型涵盖：官方新闻（事故报道、失踪公告）、小道消息（坊间传闻、黑市流言）、角色通讯（收尸任务派单、外派医疗顾问指派、势力联络）
      - 消息导向：每条消息隐性指向一个地点副本或尸体获取契机，优先选择尚未在剧情中出场的副本和功能角色，参考<功能角色总览>与<dungeon_index>
      - 悬疑留白：消息来源的认知有限，只提供引子和片面信息，不透露副本或事件全貌
      - 数量限制：状态栏最多同时存在3条消息，单次回复最多新增1条
      - 被动属性：消息是后台通知性质，如同静音手机放在兜里，{{user}}不主动查看则剧情中不暗示其存在
      - 过期判断：根据消息内容中涉及的日期与当前时间对比，若相差超过3天且{{user}}未理会，可酌情删除或更新为新消息
      - 完结删除：当某条消息导向的事件在剧情中完结后，删除该条消息

  坐标.时间:
    check:
      - 随剧情的时间流逝自然更新
      - 每次更新时，必须先读取上一次状态栏中显示的当前时间，后续更新必须以此为基准合理向前推移，禁止时间倒流、停滞或无逻辑跳跃

  坐标.当前位置.${区域|具体设施}:
    check:
      - 随主角的移动和场景切换实时更新，已知地点需严格包含<world_view>或副本列表中一字不差的地点/副本名称
      例: 黄泥湾七号站-一层大厅
地铁会展中心站-8号出口

  主角.${姓名|年龄}:
    check:
      - 初始化后通常不改变，除非剧情明确发生年龄增长

  主角.${现金|黑市信誉}:
    type: number
    check:
      - 现金用于日常购买与黑市交易，无上限；黑市信誉范围为0~100。
      - 在完成手术、售卖尸体/器官、购买改造道具等经济活动后，根据交易额或影响合理增减。

  主角.限量库存.${S病毒|智械组件|灵异注入材料}:
    type: number
    check:
      - 极度稀缺的战略物资。仅在剧情明确交代从特殊渠道获取时增加。
      - 在为尸体植入对应限量改造时严格扣除，不得透支。

  装备:
    type: |-
      {
        [装备名: string]: {
          描述: string;
          数量: number;
        }
      }
    check:
      - 随身携带的法医工具、手术器械、武器或其他特殊道具。获得时新增，消耗完毕时删除。
      - 揭下符文时结算到此(符文名和数量), 使用或粘贴符文时删除

  在场角色列表:
    type: |-
      {
        [实体标识名: string]: boolean
      }
    check:
      - 进场(insert)：当{{user}}在剧情中实际遭遇、看到或与该实体（活体或尸体）交互时，使用 `insert` 操作将其键名加入列表，值设为 `true`。
      - 离场(remove)：只要该实体的肉体不在{{user}}当前的直接视线或触及范围内，必须立刻使用 `remove` 操作将其键名从列表中彻底删除。
      - 离场触发场景：实体被收回仓库、{{user}}离开当前区域且没有明确指令带上她、双方分别、或实体自行逃离。时刻检查，避免任何实体长期留存造成提示词污染。
      - 只有在场实体才可以在正文中出现和互动，其他最多存在少量偶发远程通讯

  角色列表:
    type: |-
      {
        [角色姓名: string]: {
          ... // 具体字段
        }
      }
    check:
      - 仅可录入具有性爱可能的女角色（活人或尸体），严禁任何不适龄女性/男性或{{user}}人设被录入

  角色列表.${角色姓名}.年龄:
    check:
      - 更新时必须为number，该数字不能被引号包裹，必须为非字符串

  角色列表.${角色姓名}.${性别|背景身份|当前身份|性格}:
    check:
      - 初始化后保持稳定，仅在剧情中发生实质性改变时更新

  角色列表.${角色姓名}.生命阶段:
    check:
      - 严格只能在以下枚举值中变动：活体/濒死/死亡/改造中/成品。必须随角色状态和改造进度精准同步。

  角色列表.${角色姓名}.发色:
    check:
      - 落实到发丝的光泽度、渐变色彩、挑染痕迹

  角色列表.${角色姓名}.发型:
    check:
      - 【核心铁律】：描述必须首先包含系统识别所允许的9个大类词之一（低双马尾、盘发、麻花辫、低马尾、卷发、侧马尾、双马尾、长发、短发），必须写出具体的匹配字眼作为修饰定语或分类。
      - 发型和长短可以同时存在，可在此基础上叠加子类（例如描写双丸子头时，需写成“盘发类型的双丸子头”）。
      - 在确保包含大类关键词后，精确描写前额、鬓角、脑后及发尾各部位的具体位置与形态，说明发丝粗细软硬与垂坠感。

  角色列表.${角色姓名}.瞳色:
    check:
      - 允许异形瞳孔、异瞳、非标准纯色彩，描述由于死亡或S病毒导致的散瞳、失焦等非人特征

  角色列表.${角色姓名}.服装:
    check:
      - 使用数十字短句描述，必须包含腿部、脚部、手部、上装下装（可连体）、内衣等。尸体被脱光时写“全裸”。

  角色列表.${角色姓名}.容貌:
    check:
      - 重点勾勒面部轮廓、特征和特色评价，描写活体体温或死后青白质感。

  角色列表.${角色姓名}.身材:
    check:
      - 精确描绘骨架宽窄、各部位的肌肉线条与脂肪分布、肢体柔韧度及尸变引发的肌肉变化。

  角色列表.${角色姓名}.身高:
    check:
      - 客观描述厘米数值，格式为包含阿拉伯数字的字符串

  角色列表.${角色姓名}.罩杯:
    check:
      - 开头用大写字母（如A、B、C等）定位，然后说明形状轮廓、重心高低、乳晕颜色及触觉弹性。

  角色列表.${角色姓名}.名器特点:
    check:
      - 必须深入描写浅层到深层的肉壁质感、非标准结构、尸冷或改造带来的温度变化、人工润滑/自发液腺特性及反应。

  角色列表.${角色姓名}.当前位置:
    check:
      - 随该角色在剧情中的实际位置变动而实时更新，若是尸体存放在冷柜需明确写出。

  角色列表.${角色姓名}.种族:
    check:
      - 记录种族, 一般为人类。
      - 副本产出的特殊诡异实体种族: 僵尸(青龙陵), 寄生体(废弃温室群), 哭泣天使(废弃地下商业街), 孕尸(圣心仁爱医院), 公车艳尸(14路末班车), 异常体(8号出口), 尸变体(黄泥湾七号站), 必须严格使用简短精确的对应种族名

  角色列表.${角色姓名}.经历.过往:
    type: |-
      {
        [时段: string]: string
      }
    check:
      - 代表角色过去的人生描述，创建时至少包含5条不同时期的经历。

  角色列表.${角色姓名}.经历.初见:
    type: |-
      {
        [时段: string]: string
      }
    check:
      - 记录该角色第一次在剧情中出场前的活动轨迹，或被获取/捕获的原因。
      - 如果是死人，必须描写死前数小时活动直到死亡过程，越日常精细真实越好

  角色列表.${角色姓名}.经历.新历:
    type: |-
      {
        [日期: string]: string
      }
    check:
      - 极度精简：只记录影响剧情走向的关键节点（如死亡、上台解剖、改造完工、阵营变化）。
      - 严禁记录性爱细节，使用抽象概括词（如：发生交合、被改造穴道）。
      - 单日经历控制在50字内，连续事件必须融合为一句话。
      - 更新指令：同日经历使用replace指令，path精确到日期键名。

  角色列表.${角色姓名}.性交经历:
    type: |-
      {
        [经历时间: string]: string
      }
    check:
      - 经历对象可简化，部位名称视情况而定，次数必须是精确数字。
      - 只要不是处女就必须在这里写点什么，概括几次也行

  角色列表.${角色姓名}.孕期:
    type: |-
      {
        过往怀孕经历: {
          [时段: string]: string
        },
        当前孕期: string
      }
    check:
      - 尸体通常不适用，保留为特例及活人交互记录。

  角色列表.${角色姓名}.部位.${血管填充|内脏|骨骼|肌肉|皮肤|气味|声带|脑部|颈部|眼部|口部|胸部|小穴|宫颈|后庭|四肢|伤口|整体|外观|限量改造}:
    check:
      - 初始值: 未改造时也要记录出场时各处与健康状态不同的长期状态，置空只代表完全原生且健康
      - 触发条件：当角色/尸体在操作台上完成了具体某一项改造并固化时更新。
      - 描写规范：禁止只写干瘪的道具名。必须【同时】描述植入的零件（药剂/固件）与达成的长期效果，并且一定要【结合该角色本来的肉体特点】。
      - **变量路径仅限于部位，没有细分的已改造或现状子项，只按照已改造状态直接填写在该部位中，若无改造则填原生状态**
      - 范例：写成“注入青色药剂，原本苍白的锁骨皮肤下浮现出带尸变异质感的淡青色血管”。
