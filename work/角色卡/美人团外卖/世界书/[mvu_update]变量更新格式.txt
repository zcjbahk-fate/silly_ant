  变量输出格式:
    rule:
      - 需严格按照`<变量更新规则>`中的设定进行更新
      - 必须保证<JSONPatch>中展示`<status_current_variable>`中出现的所有字段，要一一对应，不可遗漏，不更新不代表不展示，不更新的字段op为replace，value为原值，reason为"不更新"
      - 该更新指令的工作方式遵循 JSON Patch（RFC 6902）标准，其格式必须是包含操作对象的有效 JSON 数组，但仅支持以下操作类型:
        - replace: 替换已有路径对应的数值
        - delta: 按照增量值更新已有数字类型路径对应的数值
        - insert: 向对象或数组中插入新的项目
        - remove：移除指定路径对应的内容
      - 请勿更新以`_`开头的字段名，此类字段为只读属性（例如`_变量`）
      - 当需要更新一个路径下两个变量时，先insert/replace，后delta，如:
        - { "op": "insert", "path": "${/path/to/object/}", "value": "${new_key}", "reason": "${reason}" },
        - { "op": "delta", "path": "${/path/to/object/new_key/number_variable}", "value": "${positve_or_negative_delta}", "reason": "${reason}" },
      - 最后检查是否有字段没有展示到，再次重申不更新不代表不展示
      - 变量更新前需先确认当前状态（搜索/下单/服务中/服务结束），搜索时跳过变量操作
      - 下单时：在"当前订单"对象中以女孩姓名为key插入新订单，并扣除余额
      - 服务中：更新对应角色的好感度、兴奋度、服装、姿势、心理等
      - 服务结束：将角色从"当前订单"移入"历史角色"，更新累计消费
      - 再次下单：从"历史角色"恢复数据到"当前订单"，重置服务状态和统计
    format: |-
      <UpdateVariable>
      <JSONPatch>
      [
        { "op": "replace", "path": "${/path/to/variable}", "value": "${new_value}", "reason": "${reason}" },
        { "op": "delta", "path": "${/path/to/number/variable}", "value": "${positve_or_negative_delta}", "reason": "${reason}" },
        { "op": "insert", "path": "${/path/to/object/new_key}", "value": "${new_value}", "reason": "${reason}" },
        { "op": "remove", "path": "${/path/to/key}", "reason": "${reason}" },
        ...
      ]
      </JSONPatch>
      </UpdateVariable>
